# ADR-0003：将择途定位为个人职业决策系统

## Context

择途最初来自项目发起者重新求职时的真实需要，包括筛选职位、调查公司、准备简历和沟通材料、记录结果与复盘策略。旧讨论已经扩展出职业档案、职位判断、申请材料、求职 CRM、面试准备和 Offer 比较等能力。

如果把产品定义为求职工具，边界容易理解，但无法容纳持续理解个人经历、目标和限制，以及在转型、晋升、学习投入和离职等长期职业节点继续提供决策支持的愿景。如果直接定义为职业操作系统，又会把日常工作、待办、知识管理和学习管理都纳入范围，导致产品失去中心。

## Decision

1. 择途的长期产品类别是“个人职业决策系统”。
2. 系统持续积累用户的职业事实、目标、限制、决策和真实结果，在会影响职业路径的重要选择出现时提供证据、解释、比较和行动支持。
3. 求职是第一个落地场景。产品先在求职场景验证核心价值，再逐步决定是否进入转型、晋升、学习投入、离职和其他职业选择。
4. 长期愿景不自动扩大当前范围；每个新场景仍需独立验证需求和边界。
5. 产品不扩张为管理全部日常工作、待办、知识和生活的通用个人操作系统。

## Consequences

正面影响：

* 产品拥有超越简历生成和职位聚合的稳定长期方向；
* 求职阶段积累的职业事实和结果可以成为后续职业决策的基础；
* 第一阶段仍能保持明确聚焦，不需要同时实现所有职业生涯场景；
* 可以用“是否支持重要职业决策”判断相邻需求是否属于产品范围。

代价与风险：

* “职业决策”本身仍然宽泛，需要继续明确包含和排除的决策类型；
* 持续理解职业事实会带来长期数据模型、隐私和可信度要求；
* 如果没有严格执行场景验证，长期愿景仍可能造成范围膨胀；
* 求职场景必须独立形成完整价值，不能依赖尚未实现的长期能力证明定位成立。

## Alternatives Considered

### AI 求职决策工具

只覆盖求职、申请和 Offer 选择，范围更窄，但无法自然承接求职前后的长期职业选择，未采用为长期定位。求职仍被保留为第一个落地场景。

### 个人职业操作系统

覆盖日常工作记录、待办、学习、知识管理、绩效和个人品牌，范围过宽，容易与通用效率工具重叠，未采用。

## Supersession

无。
