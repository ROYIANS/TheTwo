# 当前原型快速走查

## 目的

从产品文档、最近提交、领域状态和浏览器实际交互四个角度，对当前 React 产品概念原型形成一份可继续使用的状态认识。

## 当前产品判断

当前原型已经不是静态职位分析样张，也不是求职 CRM。它在验证一种个人职业决策操作系统：职业事实、当前方向、机会材料、研究证据、系统建议、用户决定和后续事件被保存为可追溯的关联对象；“今天”只根据已经发生的对象给出一个下一动作。

体验的主要差异化已经能够在操作中感知：

* 新用户登录后是空白但可行动的私人空间，不预置职业事实、机会、建议或面试；
* AI 过程通过输入、公开步骤、中间产物和待确认项表达，不展示私有思维链；
* AI 候选事实只有经用户逐条确认后才能进入当前职业上下文；
* 研究完成前不展示演示证据，完成后同时展示建议、来源强弱、冲突、未知项和下一动作；
* 系统建议与用户决定分开记录，“谨慎投入”不会替用户选择“申请”；
* 沟通、申请、面试、Offer、结果和策略回写由前序真实动作依次产生，未来对象不会预先作为阶段菜单出现；
* 策略回写形成新版本，不会把后来获得的信息改写成当初就已知道。

## 工程状态

原型位于 `prototype/`，使用 React 19、TypeScript 和 Vite。当前没有路由库、状态库、后端、数据库或外部请求，所有虚构数据与交互状态都在浏览器内存中。

主要边界：

* `src/domain/model.ts` 定义职业事实、机会、证据、用户决定、沟通、申请、面试、Offer、结果等对象；
* `src/app/state.ts` 通过单一 reducer 表达对象产生条件和生命周期动作；
* `src/data/demo-content.ts` 保存虚构案例和模拟 AI 产物；
* `src/features/` 按首次使用、今天、机会、面试、职业事实和 Agent 拆分视图；
* `src/components/ui.tsx` 提供对象标题、状态、证据行、过程轨迹和已发生对象链等共享表达；
* `src/App.tsx` 保持登录、当前视图、Agent 和通知等顶层编排。

最近提交完成了两轮关键演进：先把早期单体 `App.tsx` 和模拟数据拆成工程化结构，再将求职生命周期从预设阶段改为由领域动作依次产生的关联对象。最新修复让“今天”的主任务继续跟随生命周期，而不会在进入后段后退回研究阶段。

## 已识别缺口

### 面试对象在机会页的内容映射缺失（已修复）

保存面试记录后点击“回到当前机会”，页面标题和对象链都表明当前阶段是“面试”，但主内容显示“这个对象尚未发生”。领域状态和面试对象仍然存在，点击对象链中的“面试事件”可以恢复，因此问题集中在 `OpportunityView.tsx` 的 `LifecycleStage`：它处理了 `discover`、`communicate`、`applied`、`offer` 和 `outcome`，但没有处理已存在的 `interview`。

影响：对象连续性曾在一个关键返回路径上被破坏，会让用户误以为刚保存的面试记录丢失。

2026-08-13 修复：`LifecycleStage` 已补充面试对象映射。已记录面试返回当前机会时会显示现场记录、验证目标和重新打开面试事件的动作，并可以继续生成 Offer 或结果复盘。

### 私人空间文案重复（已修复）

匿名新用户登录后，页脚显示“你的的私人职业空间”。原因是顶层页脚在 `state.userName` 为空时使用“你的”，之后又固定拼接“的私人职业空间”。

影响较小，但发生在首次使用主路径，会削弱产品完成度。

2026-08-13 修复：匿名状态和已命名状态分别生成自然的所有格，首次使用页脚现为“你的私人职业空间”。

### 根 README 的项目进展已经滞后

根目录 `README.md` 仍写“尚无可运行版本”和“接下来再进入实现”，但仓库目前已经存在可启动、可完成整条虚构案例的 React 体验原型。正式产品确实尚未实现，原型也不应被描述为已经交付的产品能力；不过继续使用“无可运行版本”会掩盖当前已经建立的体验基线。

建议将公开状态改成“尚无生产可用版本；当前已有用于体验验证的本地 React 原型”，并明确链接 `prototype/README.md` 和 ADR-0024。

## 建议下一步

面试阶段映射、匿名页脚和机会材料接入区已修复；根 README 状态仍待后续更新。之后优先验证以下产品问题，而不是继续扩页面数量：

1. 用户否定或修正事实后，下游建议与材料如何生成可回看的新版本；
2. 用户选择“暂缓”或“放弃”时，下一动作和结果对象如何与“申请”分支一样完整；
3. 多个并行机会进入“今天”后，系统如何仍只给出一个可信的主任务；
4. 当前原型中的完整后续生命周期属于 MVP 后续能力，正式实现边界应继续以产品能力地图为准，不能由原型可见范围反推生产范围。
