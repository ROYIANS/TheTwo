# 职位来源与接入边界初步研究

## Research question

第一版是否应从 BOSS 直聘、V2EX、稀土掘金等渠道自动获取职位，以及哪些接入方式有官方依据？

## Conclusion

第一版不应依赖任何招聘平台的自动采集。核心入口应是用户主动提交自己从任意渠道获得的职位信息，系统负责标准化、补充调查和决策支持。

公开渠道连接器属于后续可选增强。只有存在官方接口、明确授权或可核验许可时才接入；技术上能够访问网页不等于获得了收集、复制或再利用内容的授权。

## Primary-source findings

### BOSS 直聘

* 官方网站页脚提供[协议与规则](https://about.zhipin.com/agreement)、[用户协议](https://about.zhipin.com/agreement?id=registerprotocol)和[隐私政策](https://about.zhipin.com/agreement?id=personalinfopro)。具体实现前需要重新核验当时生效版本。
* 官方 [`robots.txt`](https://www.zhipin.com/robots.txt) 对职位详情、职位推荐、带查询参数的页面等设置了广泛的 `Disallow`，包括 `/job_detail/`、`/web/geek/recommend`、`/web/geek/job-recommend` 和 `/*?*` 等路径。
* 本轮未找到面向第三方职位聚合的官方公开 API 或明确授权。

结论：不能把 BOSS 网页批量抓取或内部接口调用作为产品数据源。用户主动复制文本、提交截图、链接或在自己当前查看的页面触发本地导入，与后台批量抓取不是同一种模式，但浏览器插件的具体读取范围仍需在实现前结合届时协议和权限设计复核。

### V2EX

* V2EX 官方提供 [`API 2.0 Beta`](https://www.v2ex.com/help/api)，支持 `nodes/:node_name/topics` 等接口，使用 Personal Access Token。
* 官方文档说明 API 前缀为 `https://www.v2ex.com/api/v2/`，默认每个 IP 每小时 600 次请求，并通过响应头返回限流信息。
* [`酷工作`](https://www.v2ex.com/go/jobs) 是存在的官方节点；访问 `nodes/jobs/topics` 需要认证，本轮未使用用户令牌继续调用。
* V2EX 官方 [`robots.txt`](https://www.v2ex.com/robots.txt) 主要禁止后台、登录和设置路径，没有像 BOSS 一样禁止公开节点页面。

结论：V2EX 是目前候选渠道中官方接入依据最清晰的一个，但仍应使用用户自己的令牌或符合官方要求的访问方式，并遵守限流。它可以作为后续连接器，不是第一版成立的前提。

### 稀土掘金

* 官方[用户协议](https://juejin.cn/terms)第 10.1 条写明，未经许可不得通过机器人、蜘蛛等程序或设备监视、复制、传播、展示、镜像、上载或下载服务内容。
* 官方 [`robots.txt`](https://juejin.cn/robots.txt) 禁止搜索等部分路径，并公布文章、用户、沸点等 sitemap；robots 允许访问不等于获得内容再利用授权。
* 本轮未找到用于聚合招聘信息的官方公开 API 或明确授权。

结论：不能把掘金网页自动抓取作为第一版职位来源。用户主动提交自己看到的招聘文本、截图或链接可以作为待解析输入，但产品不能据此宣称拥有掘金职位数据源。

## Recommended first-version boundary

1. 输入渠道保持来源无关：招聘平台、公司官网、公众号、社区帖子、朋友内推、邮件或线下信息都可以进入系统。
2. 最低可用输入是职位描述或其主要内容，以及公司名称；同时尽量记录职位名称、来源渠道或 URL、采集时间、地点和薪资等原始字段。
3. 截图、文本、链接和浏览器当前页面只是输入方式，进入系统后统一保留原始内容与来源。
4. 系统可以联网补充公司与职位信息，但不能把用户提交的单条机会扩张为对来源平台的后台批量抓取。
5. 后续连接器逐个审查官方接口、授权、限流、内容权利和平台条款；没有明确依据时维持用户主动导入。

## Limitations

* 本文是产品与工程边界研究，不构成法律意见。
* 平台协议、robots 和 API 会变化，实施每个连接器前必须重新核验当时版本。
* robots 只表达自动抓取偏好或规则的一部分，不能单独证明某种使用合法或违法。
