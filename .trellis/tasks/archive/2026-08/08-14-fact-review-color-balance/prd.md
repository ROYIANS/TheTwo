# 调整待确认状态配色

## Goal

修正原型中待确认、处理中、风险和禁用操作表面与冷苔纸墨主画布之间的色温及明度冲突。语义色继续存在，但不再以大面积高暖度底色或整体透明度破坏页面层级。

## Requirements

* 保留现有冷苔纸墨视觉方向、页面结构、文案与交互行为。
* 将待确认卡片的整面暖黄色改为低饱和、偏冷的灰绿色表面。
* 芥末黄仅用于状态圆点、标签边框或其他小面积状态信号。
* 编辑区使用接近冷白纸张的表面，与卡片底色形成轻微明度差。
* 风险红继续仅用于“会影响”等风险语义，不扩大使用范围。
* 检查复用相关 token / class 的界面，避免局部修复导致其他页面失衡。
* “处理中”等警告表面保留芥末黄状态线索，但大面积底色改为低饱和冷灰橄榄色。
* 比较表中的风险与未知行保留风险红语义，底色改为带冷灰基底的浅风险色。
* 事实编辑中的主要操作在默认与悬停状态都保持深绿底、浅色文字，避免基础按钮与局部按钮选择器冲突造成深底深字。
* 主按钮禁用态使用独立的中性色阶和清晰文字，不再通过整体透明度把背景与文字一起压暗。

## Acceptance Criteria

* [x] 事实确认页中待确认卡片不再呈现大面积暖奶黄色。
* [x] “待你确认”仍能通过小面积芥末黄状态信号被快速识别。
* [x] 文本编辑区与卡片表面层级清晰，文字对比度足够。
* [x] 风险提示仍使用克制的风险红，且不与待确认状态混淆。
* [x] AI 处理过程保留明确的警告/运行中状态，但不再出现大面积奶黄色块。
* [x] 机会比较中的风险行与页面冷灰绿基底协调，风险语义仍可快速识别。
* [x] “改完确认”等局部主要操作在默认与悬停状态都有清晰文字对比。
* [x] 禁用主按钮具有明确状态与足够文字对比，不依赖整体半透明。
* [x] 桌面与手机视口无布局回归，所有既有交互保持可用。
* [x] 项目检查、构建和 `git diff --check` 通过。

## Definition of Done

* 样式改动保持在现有视觉 token 和相关选择器内。
* 使用事实确认流程进行桌面与手机截图验证。
* 不新增依赖，不修改 lockfile。

## Technical Approach

优先调整 `prototype/src/styles.css` 中待确认、警告和风险表面 token，以及 `.fact-review.inferred`、`.status-warning`、运行中分析表面和比较风险行；在最终覆盖层修正事实编辑主按钮的选择器层级与禁用态。先核对共享范围，再以最小 CSS 变更完成色温和层级修正。

## Decision (ADR-lite)

**Context**: 现有冷灰绿画布与大面积暖奶黄卡片同时承担主表面，形成色温割裂；黄色面积过大也错误提升了待确认状态的视觉权重。

**Decision**: 采用“冷灰绿卡片 + 小面积芥末黄状态 + 冷白编辑区”；警告和风险的大面积表面从画布/纸面混入少量语义色；局部主要操作显式继承主按钮前景色，禁用态使用独立中性色而不是整体透明。

**Consequences**: 页面整体会更统一，状态主要依赖标签、圆点和边界表达；因此需要验证状态仍具备足够可辨识度。

## Out of Scope

* 截图中的麦克风属于系统悬浮层，不是应用界面，本任务不处理。
* 不调整页面布局、字体、内容、功能流程或 Agent 工作台。
* 不进行与状态表面无关的全站重新配色。
