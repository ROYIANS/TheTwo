## 原始图案原子

### 1. 五段 section 框架

标准 section 不是单一居中容器，而是“窄 rail / 弹性 rail / 中央内容 / 弹性 rail / 窄 rail”。外侧 rail 在小屏仍保留窄边线，弹性 rail 只在大屏出现。

价值不在复杂分栏本身，而在于让分界线、标尺和内容边界有固定附着位置。

### 2. 分段标尺与条码刻线

* 分段标尺是一条 1px 竖线，由不同比例的实线与 `4px 实 / 4px 空` 虚线段组成。
* 条码刻线使用 `32 × 200` SVG pattern，由长度约 `8~24px`、间距约 `7~11px` 的水平 1px rect 组成。
* 条码从中央容器边缘向外生长，不是任意摆放的背景纹理。

### 3. 菱形节点

* 节点为 `6 × 6px` 正方形旋转 45 度。
* 节点中心骑在水平与竖直分界线交点，使用显式 `-3.5px` 偏移处理 1px 线宽，不依赖百分比 transform 猜位置。
* 节点属于结构层，必须高于相邻表面，不能被 header 或 section 背景裁掉。

### 4. 斜线舱壁

* 高度约 `14px`，上下各有一条全幅 1px 分界线。
* 内部是 `4 × 4`、旋转 45 度、线宽 `1.5px` 的 SVG pattern，并在上下留 1px 空隙。
* 它用于明确切换叙事段落，不作为每个 section 的机械分隔符。

### 5. 网格与点阵

* 网格通常为 `10 × 10` 或 `6 × 6`，使用 L 形路径组成细格，依靠方向性 mask 渐隐。
* 点阵通常为 `8 × 8`、半径约 `0.75px`，用于选中态或局部信息强调。
* 二者透明度都很低，且放在有结构意义的局部容器内，不满屏铺设。

## 择途的语义转译

### 2026-08-17 视觉收敛结论

用户对第一版实现的视觉检查确认：同时采用边轨、条码、菱形、舱壁、网格和点阵，会让首页从“结构化”滑向“装饰堆叠”；菱形节点也过于接近参考项目的品牌识别。最终采用边界因此收窄为：

* 只借鉴工程纸的秩序方法，不复制菱形节点等标志性符号；
* Hero 允许一组低对比线性边轨，产品预览允许一层局部研究网格；
* 同一区域最多一种主导纹样，纹样之间用留白而不是更多分隔器建立层级；
* 页面识别度由冷苔绿纸面、编辑式中文标题、非对称留白和真实工作流预览共同建立；
* Header 必须属于同一冷色主色体系，不能形成偏粉的独立色带。

### 采用

1. **Hero 研究轨道**：首屏只保留低对比线性边轨，表达“职业事实和机会证据沿同一研究过程推进”；不再叠加条码或节点。
2. **产品预览网格**：在机会研究台预览内部保留低透明 10×10 网格，从右下向正文方向渐隐，强化“研究现场”而不影响读数。

### 不采用

* 不使用 zed 的噪点图片、冷蓝品牌色、巨型旋转几何水印和描边大 logo。
* 不把每个 section 都套完整五段 rails；择途正文保留当前更安静的档案排版，只在 hero 建立一次识别性框架。
* 不使用菱形节点、条码刻线、斜线舱壁和独立点阵；这些元素与剩余边轨、网格同时出现会制造噪声，也会过度接近参考项目。
* 不添加 `PRO / 01`、坐标、伪读数、技术代号等无业务含义文字。
* 不让网格、点阵或条码进入按钮、正文底层或移动端狭窄阅读区。
* 不复制 `vidorra-life` 的组件代码；只按原始几何参数在 prototype 内实现最小原子。

## 实现约束

* SVG pattern id 使用 React `useId()` 派生，避免页面内多个 pattern 发生全局 id 冲突。
* 所有图案 `aria-hidden`、`pointer-events: none`，不进入可访问性树，也不阻挡操作。
* 色彩只使用 prototype 现有 `--line`、`--line-strong`、`--primary`、`--blue` 等 token。
* 装饰透明度保持在约 `0.08~0.22`；节点与结构边线可以使用正常对比度。
* 移动端隐藏复杂 rail，只保留不造成横向溢出的普通分界和局部网格。

## 验证点

* `1440 × 900` 能看到克制的 hero 线性边轨和产品预览网格，且正文对比度不下降。
* `820 × 1180` 与 `390 × 844` 无横向溢出，图案不遮挡 CTA、标题、读数或预览入口。
* `prefers-reduced-motion` 不影响静态图案；图案本身不做持续动画。
* 首页进入 onboarding、退出回首页和 GitHub Pages 构建保持通过。
