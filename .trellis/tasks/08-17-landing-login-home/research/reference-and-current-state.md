# 首页改造：当前状态与参考项目结论

## 当前 prototype

* 根组件 `prototype/src/App.tsx` 在 `state.authenticated === false` 时只渲染 `LoginScreen`；点击按钮触发本地 reducer 的 `login` action，没有真实认证 API。
* `LoginScreen` 当前是“私密档案封面”式双栏卡片，已经有择途品牌、个人空间表达和演示边界，但不具备完整落地页的信息层级。
* 登录后进入 onboarding，现有 reducer、路由式 view 切换和业务页面不需要为首页改造而重写。
* prototype 使用 React 19、Vite 7、TypeScript 与 Phosphor Icons；没有路由库，也没有测试框架。可用检查是 `check` 与 `build`。
* 当前前端规范要求保持 reducer 作为单一状态真相、使用 Phosphor 图标、不新增依赖，并保持 GitHub Pages 构建兼容。

## 产品文档漂移

* `docs/product/product-brief.md` 和 `docs/decisions/0022-isolated-multi-user-self-hosting.md` 仍将首版定义为“一个实例支持多个隔离用户”。
* 本次用户明确把产品收窄为“独立部署、一个实例只服务一个人、保存该用户的信息”。
* 已接受 ADR 不能原地改写含义，因此应新增 ADR-0025 取代 ADR-0022，并把 ADR-0022 状态标记为 `superseded`、补充替代链接。
* 产品摘要需要同步删除账户邀请、实例管理员和共享凭据等多人实例语义，改为单所有者账户和实例级数据边界。

可复用的是设计方法，不是品牌资产：

* 工程纸式全幅分界线、细网格、节点和标尺负责建立秩序，不依靠装饰卡片堆叠。
* 暖/冷中性纸面、深墨文字、单一品牌强调色与少量语义色形成稳定层级。
* UI 正文使用无衬线，品牌叙事和关键判断使用中文衬线。

* 登录页和落地页保持同一视觉语汇，认证入口不是脱离产品叙事的通用表单。

不照搬的部分：

* 不复制滴茶的暖棕品牌、物品空间概念、品牌图形或具体文案。
* 不移植复杂导航抽屉、主题系统、HeroUI 或参考项目的组件抽象。
* 不添加没有业务含义的工程编号、坐标、代号或大量装饰纹样。
* 不把择途首页扩展成九段式长营销页；个人自用产品应更直接、更安静。

## 方案比较

### A. 完整融合首页（采用）

首屏左侧承担品牌与定位，右侧同时展示真实工作流预览和唯一用户入口；下方用少量结构化 section 解释工作方式、数据边界与产品承诺。

优点：真正完成“落地页 + 登录页融合”；无需弹窗；未来可在原入口位置替换成真实认证表单。

代价：首页组件和样式需要一次较完整的重构。

### B. 扩充现有登录卡片

保留现有双栏卡片，只补产品定位、部署与隐私说明。

优点：改动小。

代价：仍然更像登录封面，无法承担完整产品方向表达，移动端信息密度也会失衡。

### C. 独立落地页 + 登录弹窗/二级页

营销叙事与认证分离。

优点：认证模块边界传统清晰。

代价：直接违背本次“融合首页”目标，增加导航与浮层复杂度。

## 采用的页面结构

1. 顶部品牌栏：择途 / THE TWO、页面内锚点、唯一主行动。
2. 首屏：产品定义、单用户/独立部署事实、真实工作流预览、演示进入入口。
3. 工作方式：职业事实源 -> 机会研究 -> 申请决策包，强调连续性而非功能列表。
4. 数据边界：一个实例、一个所有者账户、信息保存在自己的部署环境；外部服务只发送当前任务所需信息。
5. 产品承诺：AI 提供证据和建议，用户保留解释权与最终决定权。
6. 收尾入口：再次进入个人空间，不提供注册、邀请或团队入口。

## 风险与验证

* 当前是演示登录，文案必须明确，不能让用户误以为已实现密码、加密或完整本地持久化。
* 首屏内容较现有页面多，需要重点验证 360px 左右移动视口的文字换行、导航适配和按钮宽度。
* `App.tsx` 仍只根据 `authenticated` 切换页面；首页组件不得另造认证状态。
* 需要运行 TypeScript check、Vite build，并通过桌面/移动截图检查布局与实际点击进入流程。
