# ADR-0009：采用开源自部署且不提供官方 SaaS 的产品模式

## Context

择途会保存职业经历、薪资和求职偏好、公司接触记录、AI 对能力的推断以及面试和 Offer 结果。这些数据高度敏感。项目可以通过官方 SaaS 托管数据和模型调用，也可以采用由用户自己部署、自己选择模型服务的开源模式。

官方 SaaS 更容易服务非技术用户，并能通过订阅、托管和集中数据形成收入；但用户必须把长期职业数据交给平台，也会让项目的商业利益与数据控制发生潜在冲突。项目发起者开源择途的主要原因之一，就是希望用户能够自行部署和掌控这些数据。

## Decision

1. 择途采用开源、自部署优先的产品模式。
2. 项目不把官方集中式 SaaS 作为当前或预设的商业路线。
3. 用户职业画像和求职记录默认保存在用户自己控制的部署环境中，项目不依赖集中收集这些数据形成商业价值。
4. BYOK 是标准能力，用户自行选择并承担外部模型服务。
5. 项目核心优先免费使用；当前更匹配的可持续方向是个人或组织赞助，具体赞助机制以后决定。
6. 是否允许闭源付费扩展、付费支持或其他收入方式尚未决定，不能从本决策推导为已接受。

## Consequences

正面影响：

* 用户能够掌控高度敏感的职业数据和模型访问；
* 项目的可信承诺不依赖用户相信一个集中式平台长期不滥用数据；
* 社区可以检查、部署和改进系统；
* 模型提供商和部署环境保持可替换。

代价与风险：

* 放弃官方 SaaS 订阅、托管模型差价和集中数据网络效应等商业路径；
* 自部署会提高非技术用户的安装、升级、备份和故障处理门槛；
* BYOK 要求用户理解模型供应商、费用和数据发送边界；
* 赞助收入不稳定，项目长期维护仍需寻找可持续机制；
* 长期服务所有中文求职者的目标与自部署门槛之间存在张力，需要另行解决。

## Alternatives Considered

### 官方 SaaS 优先

使用门槛和商业化路径更直接，但需要集中托管敏感职业数据，与开源和用户数据控制的初衷冲突，未采用。

### 完全离线且只允许本地模型

数据控制最强，但会限制公司网络背调和用户选择云端模型的能力，未采用。用户仍可自行选择完全本地的部署方式。

### 开源自部署加官方托管服务

常见且具备商业可行性，但发起者当前明确不计划经营 SaaS，因此未采用为预设路线。未来若改变，需要新的决策记录替代本决策。

## Supersession

无。
