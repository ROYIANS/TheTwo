## 择途是什么

择途希望持续理解一个人的真实经历、能力、目标和限制，在重要职业选择出现时，帮助用户看清选项、理解取舍、准备行动，并根据真实结果调整后续策略。

它不是又一个只会生成简历或罗列职位的 AI 工具。择途长期积累的核心是由 AI 协助建立、由用户拥有并持续演化的职业画像与决策记录。

求职是第一个落地场景，但不是产品的最终边界。

## 为什么做择途

求职者面对的往往不是“有没有职位”，而是更困难的问题：

* 这个岗位和公司提供的信息是否真实、完整、可信？
* 它是否符合我的能力、目标、现实限制和长期职业方向？
* 为这次机会投入时间是否值得，还有哪些机会成本？
* 我应该怎样基于真实经历表达自己，而不是让 AI 编造一个更漂亮的人设？

择途的核心承诺不是保证 Offer，也不是帮助用户投递更多职位，而是提高职业决策质量与掌控感。

## 第一版面向谁

第一版优先服务：

> 正在主动求职、有数年真实项目与职业积累的中文软件工程师。

项目发起者本人是首位真实用户。产品会先深入理解前端、后端和全栈等软件工程岗位，再基于真实需求逐步扩展到更多职业。

这是产品承诺与适配优先级，不是使用限制。应届生、非软件职业人群和暂未求职的用户仍可以使用未来的开源版本，但第一版不会假装已经充分理解所有行业与职业场景。

## 第一版希望完成的闭环

```text
现有简历或基本经历
  -> AI 结构化访谈
  -> 建立并由用户确认职业画像
  -> 从一份职业事实源派生多个简历定位
  -> 用户从任意渠道采集职位
  -> 调查和标准化岗位与公司信息
  -> 给出明确但非强制的行动建议
  -> 为值得申请的机会生成完整申请决策包
  -> 用户亲自沟通和投递
```

职位可以来自招聘平台、技术社区、公众号、公司官网、朋友内推、邮件或线下消息。第一版不依赖平台级职位聚合；只要用户提供公司名称和 JD 或主要职责要求，系统就可以开始调查和分析，并明确展示仍然缺失的信息。

完整申请决策包将围绕已确认的职业事实，准备岗位定制简历、打招呼内容、应重点强调的经历、需要向招聘方确认的问题，以及当前风险与未知项。

## 产品原则

* **用户拥有最终解释权**：AI 可以主动理解和质疑，但不能替用户定义自己。
* **证据优先**：区分事实、用户确认内容、AI 推断、价值判断和未知项。
* **明确建议，不替用户决定**：给出“值得投入”“谨慎投入”或“暂不投入”等行动建议，同时解释依据和不确定性。
* **不编造经历**：所有申请表达都应追溯到用户真实做过的事情。
* **不自动海投**：不冒充用户沟通，不自动提交申请，不以投递数量作为成功标准。
* **隐私与数据控制优先**：自部署、BYOK，外部模型和联网服务遵循最小必要披露。
* **核心能力持续开源免费**：不采用以闭源高级能力削弱社区版本的 open-core 模式。

## 明确不做

择途当前不以这些方向作为产品基础：

* 自动海投和招聘平台代操作；
* 绕过平台限制的大规模职位爬取；
* 没有解释依据的综合匹配分；
* AI 补写用户没有做过的经历、职责或成果；
* 面向企业的招聘筛选系统；
* 集中托管用户职业数据的官方 SaaS；
* 第一版同时覆盖所有职业人群和完整职业生涯场景。

## 当前进展

当前阶段主要完成产品愿景、目标用户、AI 权力边界、可信原则和第一版范围的定义。接下来会继续拆解机会判断方法、职业画像模型、产品交互和技术方案，然后再进入实现。

项目采用文档与 spec 驱动的开发方式。重要讨论、决策和后续实现任务会持续保留在仓库中，而不是只存在于一次 AI 对话里。
