# ADR-0018：一份职业事实源派生多个简历定位版本

## Context

有经验的软件工程师可能同时适合高级前端、前端架构、全栈等不同职责岗位。系统可以要求用户只维护一个当前方向，可以生成一份包含所有能力的综合简历，也可以从统一职业事实中派生多个定位版本。

单一方向更聚焦，但限制合理的并行探索；综合简历容易定位模糊；多个完全独立的简历又会造成事实漂移和维护重复。

## Decision

1. 职业画像与能力证据是唯一职业事实源。
2. 系统支持从同一事实源派生多个岗位定位版本，例如高级前端、前端架构和全栈。
3. 不同定位版本可以选择、排序、压缩和强调不同经历，但不能产生相互矛盾的事实。
4. 用户修正职业事实后，相关定位版本应能够识别并同步受影响内容。
5. 针对具体 JD 的岗位定制简历以某个定位版本为起点继续裁剪，不从空白重新生成。
6. 简历中的新表达不能自动反向成为职业事实，除非用户确认并纳入职业画像。

## Consequences

正面影响：

* 用户可以同时探索多个合理岗位方向；
* 所有简历版本共享同一套可信事实；
* 针对具体岗位的定制更快且定位清晰；
* 修正事实时能够追踪受影响的材料版本。

代价与风险：

* 多个定位版本需要清晰的版本关系和变更提示；
* 用户可能创建过多方向并分散求职精力，系统需要帮助比较优先级；
* 同一经历在不同版本中的压缩和表述可能仍产生语义偏差；
* 招聘平台在线简历与附件简历的版本使用方式可能不同，需要后续适配。

## Alternatives Considered

### 只维护一个当前求职方向

最聚焦，但无法支持用户合理地探索不同职责岗位，未采用。

### 只维护一份综合通用简历

维护简单，但容易定位模糊，无法针对招聘方关注点快速表达，未采用。

### 每个岗位从空白生成简历

表面上最灵活，但容易产生事实漂移、重复确认和版本混乱，未采用。

## Supersession

无。
