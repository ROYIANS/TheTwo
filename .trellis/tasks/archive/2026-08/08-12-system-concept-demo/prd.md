# 探索择途系统概念 Demo

## Goal

制作接近成熟产品体验的择途系统概念 Demo，让用户能够直观感受“择途作为一个完整系统是什么”。任务先通过四种结构明显不同的产品骨架完成方向比较，随后基于用户选择的 D“职业决策研究台”和 MiroFish 源码研究，收敛为一份独立 Demo。Demo 使用虚构数据，只验证信息架构、工作入口、对象关系和视觉气质，不形成正式前端实现方案。

## Context

* 已完成的 MVP 体验主干原型验证了六阶段流程基本成立，但它仍是流程演练器，不具备完整系统概念。
* 用户希望看到一个更“高大上、精致、参考成熟产品”的系统 Demo 网页。
* 产品核心对象包括职业画像、求职方向、方向表达、机会、调查证据、机会判断和申请决策包。
* AI 必须嵌入具体任务与对象上下文，不做孤立的通用聊天首页。
* 当前没有正式前端工程、路由、组件库或 code-spec；本任务仍是独立实验原型。

## Design Question

择途采用怎样的系统级信息架构和工作台结构，才能让用户每天打开后迅速知道：

1. 现在最值得处理什么；
2. 系统掌握了哪些当前有效职业上下文；
3. 哪些机会值得投入、依据和未知项是什么；
4. 如何从机会判断进入申请准备；
5. AI 顾问如何在不夺取用户控制权的前提下持续工作。

## Product Shape Clarification

2026-08-12 用户进一步确认：择途不是以列表、台账和 CRUD 为中心的管理型系统，而是以个人职业事实、机会材料和持续研判为中心的研究型系统。

系统主链应表达为：

1. **建立职业事实源**：首次使用时，通过上传现有简历、AI 结构化访谈、表单补充和用户确认，形成个人信息、真实经历、能力证据、职业目标、期望与硬约束；
2. **收集研究对象**：用户通过浏览器插件、截图、粘贴、导入和合规的公开渠道，把职位、公司与相关材料带入系统；系统负责拉取用户授权内容、解析、去重和结构化，不把这一阶段设计成传统职位管理后台；
3. **开展机会研究**：以单个机会为持续对象，在分阶段、分栏的研究台中完成主体核验、证据调查、职业匹配、风险与未知项识别、判断形成和申请准备；
4. **形成研究成果**：输出可追溯的阶段判断、待确认问题、申请材料和完整申请决策包，由用户作最终决定；
5. **用结果修正理解**：根据后续沟通、面试、Offer 和真实求职结果更新职业事实、假设和策略。

因此，独立 Demo 需要覆盖“职业事实源建立 -> 研究对象收集 -> 机会研究台”的完整产品主链。机会列表、状态和历史只承担研究入口与恢复上下文，不成为产品主角。

## Requirements

* 使用一个自包含 HTML 文件，无框架、构建工具、服务器、网络请求、真实 AI 或数据持久化。
* 使用虚构的资深前端求职者“林舟”、虚构公司、职位、证据和申请材料。
* 提供四个结构明显不同的系统方案，通过 URL `?variant=A|B|C|D` 和固定底部切换器选择。
* 支持键盘左右方向键切换方案，不在输入控件聚焦时拦截。
* 四个方案共享同一组产品数据和核心页面，但不得只改变颜色与装饰。
* 至少提供以下可导航界面：
  * 今日 / 工作台；
  * 机会列表；
  * 单个机会的证据与判断详情；
  * 职业画像；
  * 简历与申请材料。
* 首页应优先回答“今天最值得处理什么”，而不是展示营销文案或功能介绍。
* 机会详情必须具体呈现事实、证据、推断、未知项、风险、匹配与明确建议。
* 系统建议与用户最终决定保持分离；申请材料不能隐藏风险和未知项。
* 职业画像必须体现已确认事实、AI 推断、证据和更正历史的区别。
* AI 顾问必须与当前页面或对象绑定，明确自己正在处理的上下文。
* 系统应体现自部署、个人空间、外部服务授权和数据控制，但不让设置内容抢占主要工作区。
* 界面使用成熟运营型产品的信息密度和交互层级，不制作营销 Hero、卡片瀑布、渐变背景、玻璃拟态或装饰性大图。
* 桌面和移动端均能查看核心内容并完成页面与方案切换。
* 页面明确标记为概念 Demo，不能暗示能力已经实现。

## Variants

### A：决策工作台（默认推荐）

* 左侧稳定产品导航；
* 中央以“今日决策队列”和机会对象为主；
* 右侧是随当前对象变化的 AI 顾问与上下文；
* 强调反复工作效率、任务连续性和对象关系。

### B：职业简报

* 顶部全局导航；
* 首页像一份每日职业简报，以编辑化层级组织当前方向、机会变化和关键判断；
* 进入对象后采用宽幅阅读与证据叙事；
* 强调理解、反思和掌控感，降低传统后台感。

### C：决策台账

* 紧凑命令栏与高密度表格 / 列表；
* 当前对象使用可展开检查器展示证据、风险和下一动作；
* 强调快速扫描、比较和批量审阅少量机会；
* 不引入黑盒总分或自动排名。

### D：职业决策研究台

* 参考用户提供的 MiroFish 截图所体现的研究工具气质，但不复制其品牌、内容和视觉细节；
* 顶部使用紧凑的模式导航与当前阶段状态，形成“正在完成一项职业决策工作”的连续感；
* 以宽幅双栏为核心：左侧展示可阅读、可追溯的职业判断报告，右侧展示调查证据、Agent 工作过程和围绕当前对象的交互；
* 使用黑白、中性灰、细边框、点阵纹理、衬线报告标题和少量绿色状态色，形成冷静、严谨、研究型工作台气质；
* 机会列表采用证据调查队列，职业画像采用事实档案，材料页面采用正文与校订记录并列，不把所有页面强行做成同一种仪表盘；
* 可以展示有限的 Agent 过程可见性，但不得用虚假的实时日志、夸张运行数字或技术控制台掩盖产品结论；
* 不引入与求职决策无关的巨型关系图；关系视图只在确实帮助理解公司、岗位、证据和人物关系时出现。

## Shared Demo Data

* 用户：林舟，8 年前端与全栈经历；
* 主方向：资深前端 / 前端架构；
* 并行方向：偏前端的全栈工程师；
* 当前机会：澄屿科技、岸线云、折光智能、远岚网络；
* 系统建议状态：值得投入、谨慎投入、暂不投入、等待信息；
* 待办：确认澄屿工作方式、审核岸线云定制简历、纠正一条职业画像推断；
* 当前材料：方向简历、Boss 平台档案、两个职位定制版本；
* 横切状态：事实、推断、未知项、证据来源、更正记录、系统建议和用户决定。

## Interaction

* 主导航可切换各系统界面；
* 点击机会可以进入详情；
* 首页的主要行动可以跳转到对应对象；
* 机会详情可以切换证据、匹配、申请准备等子视图；
* 方案切换保留当前系统界面，便于对照同一内容；
* 移动端使用可打开的全局导航或紧凑顶部切换，不删除核心功能。

## Final Convergence Demo

四方案对比稿继续保留为设计过程证据；另建一份只呈现择途最终方向和完整主链的独立 HTML Demo，不再显示 A/B/C/D 方案切换器。

* 独立 Demo 包含三个连续空间：职业事实源、研究资料库和机会研究台；
* 首次使用从职业事实源开始，通过简历导入、基本表单、AI 结构化访谈和用户确认形成最低可信职业上下文；
* 研究资料库支持以截图、粘贴、浏览器插件、导入和合规公开来源的概念入口带入材料，展示解析、去重、来源保留和待研究机会；
* 从研究资料库选择一个机会后进入机会研究台，当前用户事实、目标、硬约束和原始职位材料持续成为研究上下文；
* 以“同一个机会对象持续贯穿工作”为核心，机会详情内部承载采集结果、调查、判断、申请准备和用户决定；
* 顶部同时呈现当前对象、局部工作阶段和调查状态，但不把全站伪装成一次性线性向导；
* 机会深度工作区提供三种观察方式：双栏研判、专注结论、专注证据；切换只改变排布，不丢失当前机会和子视图；
* 当前独立 Demo 不使用关系图。左侧以机会档案、阶段成果、职业匹配与硬约束为核心；未来只有当人物、公司、岗位与证据之间的关系本身会改变判断时，才按需提供局部关系视图；
* 调查阶段右侧呈现来源、冲突、未知项和用户可理解的调查活动，开发者日志不默认出现；
* 判断形成后保留左侧阶段性报告，右侧可在证据审计与对象化顾问之间切换；
* 顾问操作使用明确任务语义，包括质疑建议、补充事实、生成待问招聘方问题和进入申请准备，不提供孤立通用聊天首页；
* 移动端按结论、风险与未知、证据、顾问行动重排，并以抽屉或分段视图承载次要上下文；
* 保持自包含、可直接打开、虚构数据、无网络请求和无真实 AI 能力，并显著标记为概念 Demo。

## Design Direction

* 目标用户：正在主动求职、有多年经验、需要反复比较真实机会的中文软件工程师。
* 品牌气质：冷静、可信、锋利但不压迫；像一位有证据意识的职业顾问，而不是招聘平台或内容生成器。
* 视觉品质：成熟 B2B 产品的精确结构，加少量编辑化气质；多种中性色配合克制的绿色、铜色、蓝色和风险红。
* 核心记忆点：每个重要结论旁边都能看见依据、未知项和下一行动。
* 约束：不把所有内容装进圆角卡片，不嵌套卡片，不使用单一深蓝 / 紫色主题，不靠渐变和发光制造高级感。
* 新增参考方向：研究报告与工作过程同屏，黑白克制、高信息密度、细边框与明确状态；择途应保留人的职业叙事和决策温度，不能退化成仿真的技术控制台。

## Out of Scope

* 正式 UI 规范、设计系统、组件 API、路由与工程结构；
* 真实认证、上传、搜索、OCR、模型、数据库和导出；
* 完整设置后台、管理员界面与部署流程；
* 求职申请后的面试、Offer 和结果反馈完整界面；
* 将任一方案代码直接用于正式产品。

## Decision (ADR-lite)

**Context**：单一系统稿容易过早把一种视觉结构误当成产品答案，且用户很难仅通过描述判断信息架构偏好。

**Decision**：在同一自包含 Demo 中实现四种结构差异明显的系统方案，共享同一数据和页面任务，通过固定切换器直接比较。用户实际体验后确认选择 D“职业决策研究台”作为后续系统概念基线；A、B、C 保留为比较来源，不再作为并列候选。D 的信息层级、页面工作流、分栏比例、状态反馈和交互细节仍需继续调整。

**Consequences**：后续迭代围绕 D 收敛，可以吸收其他方案或外部参考中适合择途的局部做法，但不再维护四套同等深度的设计。原型代码仍必须被视为一次性材料，最终实现需要基于确认后的产品契约重新设计，而不是直接清理后投产。

## Accepted Direction

2026-08-12 用户确认 D“职业决策研究台”最符合择途的系统方向。对本地项目 `C:\Users\12946\Downloads\MiroFish-main` 的源码研究进一步确认，D 应借鉴其工作流连续性，而不是复制黑白配色、巨型图谱或技术控制台：

* 同一个职业决策对象应贯穿采集、调查、判断、申请准备与用户决定，页面和路由需要允许恢复最近有效工作点；
* 顶部应同时表达“当前对象所处阶段”和“调查或资料状态”，视图模式只改变观察密度，不改变任务上下文；
* 深度研判页应让阶段性结论与证据调查过程同屏，明确区分事实、推断、未知项和来源；
* 调查完成后保留判断正文，把右侧从调查活动切换为围绕当前对象的顾问交互，避免进入聊天后丢失成果上下文；
* 用户可理解的调查活动与开发者诊断日志必须分层，后者默认隐藏，不能用过程复杂度冒充可信度；
* 双栏只用于适合深度研判的页面；机会列表、今日工作台等页面按任务采用更合适的布局；
* 桌面双栏是增强模式，移动端按“结论、风险与未知、证据、顾问行动”重新排序，不复制固定 50/50 分栏与最小栏宽。

当前精修不再把“形似 MiroFish”作为验收目标。真正需要保留的是：当前机会持续在场、阶段成果与当前工作并列、用户能立即识别已有结论与下一动作；黑白配色、点阵背景、关系图和过程日志都不能代替这些产品关系。

D 下一轮优先调整对象连续性、局部阶段反馈、结论与证据的关联，以及调查完成后的顾问切换；视觉装饰和技术感只服务这些关系。
