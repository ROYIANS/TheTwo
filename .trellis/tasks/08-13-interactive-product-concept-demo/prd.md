# 构建完整交互产品概念 Demo

## Goal

制作一份可以启动、操作和继续演进的纯前端 React 原型，用一个完整虚构案例验证择途从职业事实建立、机会材料接入、证据调查、机会判断到申请准备和用户决定的连续产品体验。

## Design Question

择途当前产品设计能否在不依赖真实后端、模型和正式技术栈的前提下，被表达为一段完整、可信、可操作的产品体验，并让用户清楚感受到：职业事实如何约束判断，证据如何支撑结论，AI 建议如何与用户决定分离？

## Prototype Nature

* 这是产品原型和前端工程化 Demo，不是生产实现；React + Vite 只服务于原型迭代，不形成后端、数据库或生产部署决策。
* 使用 React、TypeScript、Vite 和纯 CSS；不引入 UI 组件库或真实后端。
* 原型数据和状态只存在于浏览器内存；刷新后恢复“首次使用”状态，不预置已经完成的职业事实、机会研究或面试进度。
* 原型用于验证产品结构、UI 和交互，不能暗示任何能力已经实现。

## Design Context

* 目标用户：正在主动求职、有多年项目和职业积累、需要判断真实机会的中文软件工程师。
* 核心任务：建立可信职业上下文；带入职位；审视调查证据；理解建议、风险与未知项；审核申请材料；作出申请、暂缓或放弃决定。
* 品牌气质：冷静、可信、锋利但不压迫；像有证据意识的职业顾问，而不是招聘平台、内容生成器或技术控制台。
* 视觉方向：成熟、克制的职业决策研究台；高信息密度、清晰层级、少量编辑化气质；结论与证据同屏。
* 核心记忆点：任何重要结论旁边都能看到依据、未知项和下一行动。
* 交互原则：用对象与关系表达当前现实，用时间性的动作与快照表达变化；用户始终可以质疑、修正、停顿和回看，AI 建议不收缩用户的最终判断权。

## Complete Example

* 用户：林舟，8 年前端与偏全栈经历，正在寻找资深前端或前端架构方向机会。
* 当前硬约束：期望薪资不低于 30K、拒绝长期 996、优先上海或可接受混合办公。
* 当前机会：澄屿科技的资深前端工程师岗位。
* 原始材料：职位文本、来源 URL 元数据和虚构截图占位。
* 调查证据：官网、企业登记、招聘描述、公开访谈和匿名评价信号，明确区分证据强弱与冲突。
* 系统建议：谨慎投入；同时展示匹配点、不利证据、未知项和改变结论的信息。
* 最终产物：岗位定制简历摘要、初次沟通草稿、重点经历、表达边界、招聘方待确认问题和用户决定。

## New User Journey

本轮重设计必须以一个完全新用户的视角展开。用户第一次登录时只拥有一个空白但可行动的私人空间，不应看到虚构案例已经产生的结论、进度、机会或面试。

```text
进入私人空间
  -> 选择最轻的起点：导入简历/经历，或直接开始一次职业访谈
  -> AI 展示材料读取、候选事实、缺失和冲突
  -> 用户逐条确认、修正或否定职业事实
  -> 确认当前求职方向、硬约束和可权衡偏好
  -> 生成第一个“今天”：当前状态、待补信息和一个下一动作
  -> 用户带入第一份职位材料
  -> AI 解析职位并创建机会对象草稿，用户确认后才成为当前机会
  -> 研究任务逐步产出证据、未知项和可质疑建议
  -> 用户决定申请、暂缓或放弃
  -> 后续沟通、面试、Offer、结果作为机会关联对象逐步产生
  -> 结果只生成待确认的职业事实/策略回写，不自动覆盖当前事实
```

首次使用的关键不是填完一张完整表单，而是让用户看见：系统如何理解他、哪些理解还只是推断、下一步为什么值得做。预置案例只作为用户完成带入后由操作逐步生成的演示数据，不能作为登录后的初始状态。

## Core Experience

1. 职业事实源：浏览已确认事实、AI 推断、未知项和证据；确认或否定一条推断；完成当前方向的最低可信上下文。
2. 研究资料库：从粘贴职位文本开始，查看解析结果、原始来源、缺失和冲突；创建机会研究对象。
3. 机会研究台：按“机会档案 -> 证据调查 -> 机会判断 -> 申请准备 -> 用户决定”推进，同一机会和职业上下文持续在场。
4. 证据与建议：支持查看证据详情、切换结论/证据视角、质疑建议并看到建议依据。
5. 申请决策包：审核材料、编辑沟通草稿、确认风险和待问问题，最后选择申请、暂缓或放弃。
6. 状态反馈：关键操作应即时更新进度、状态、下一动作和界面反馈，不调用真实服务。

## UI Requirements

* 默认首屏为模拟登录入口，登录后直接进入可工作的产品界面，不制作营销落地页。
* 桌面采用当前对象上下文和主工作区；深度研判页使用结论与证据双栏，空间切换不通过常驻菜单完成。
* 移动端重新排列为当前结论、风险与未知、证据、操作，不简单压缩桌面双栏。
* 使用熟悉图标表达导航和工具操作，图标按钮提供 tooltip/可访问名称。
* 不使用卡片套卡片、玻璃拟态、发光、紫蓝渐变、装饰性大图、巨型指标或黑盒综合分。
* 页面文字和控件在常见桌面、平板和手机宽度不重叠、不截断，关键操作可达。
* 不使用固定概念警示横幅；模拟边界在登录说明和具体操作反馈中按需表达。

## Interaction Requirements

* 用户从“今天”的主任务、事件和相关对象进入职业事实、机会、面试等上下文；对象间跳转保留当前示例状态和机会阶段。
* 职业事实中可以确认/否定 AI 推断，状态变化影响完成度和后续提示。
* 资料库中可以执行模拟解析、检查字段、创建机会对象并进入研究台。
* 研究台阶段可前进和返回；选择证据时右侧/移动端详情随之变化。
* 判断页支持质疑建议、补充一条用户事实并看到建议说明更新。
* 申请页可以切换材料区、编辑沟通草稿、勾选审核项，并作出申请/暂缓/放弃决定。
* 用户决定与系统建议始终分开显示，覆盖建议不修改历史判断。
* AI 过程可见以证据、输入范围、公开假设、任务步骤、中间产物和待确认项表达，不展示或伪造模型私有思维链。
* 新用户的每个关键产物都通过领域动作产生：导入材料、确认事实、确定方向、创建机会、启动研究、记录事件、作出决定和回写复盘；动作反馈要说明影响对象与下一步。
* 支持键盘焦点、Escape 关闭浮层、`prefers-reduced-motion`。

## Scope Update: Experience Upgrade

用户确认当前原型需要从“机会研究后台”升级为可持续使用的个人职业操作系统概念原型：

1. 首次进入必须有登录模拟窗口，登录后才进入个人空间，并支持退出回到登录界面。
2. 视觉和信息架构从传统后台/CRM 转为个人工作台，以“下一步行动、当前机会、AI 正在处理什么、用户需要决定什么”为主。
3. AI 研究与分析过程必须可见：展示研究任务、处理中状态、来源读取、分析步骤、待用户确认项和完成结果，不能只是瞬时黑盒按钮。
4. 任意主要页面都可以打开持久的 Agent 对话面板；对话与当前职业事实、机会或面试上下文绑定，并能产生下一步行动建议。
5. 原型可浏览完整求职生命周期：发现、研究、沟通、申请、面试准备、面试进行、反馈复盘、Offer 比较、结果记录和策略调整。
6. 删除所有只用于装饰的英文编号眉题，例如 `RESEARCH LIBRARY / 02`、`OPPORTUNITY DESK / ...`；页面标题和状态文字必须直接服务于理解与行动。
7. 以上内容只扩大体验原型的可见范围，不决定正式前后端技术栈，也不把 MVP 后续能力伪装成已经实现。

### UI Refinement After Review

用户进一步确认：

* Agent 只保留一个全局入口，避免左下角、右上角和页面标题旁重复出现；全局入口应固定、可预期，并且不抢占当前任务的视觉层级。
* 删除传统左侧后台式侧边栏，不再用顶部轻量导航表达长期空间；由当前对象、事件和下一动作承载进入关系。
* 内容页不再用圆形 AI 按钮或重复的“打开 Agent”操作；随时对话通过唯一全局入口完成。

用户最新确认：固定 header 也会让产品保持后台应用的框架感，因此当前原型采用“无壳工作台”方向：

* 不使用固定 header、左侧栏或传统全局导航栏；
* 页面内容先呈现当前身份、当前机会和下一步行动，不再常驻展示“今天、机会旅程、面试与复盘、职业底座”等空间菜单；
* “今天”是唯一工作起点，用户直接点击当前机会、下一场面试或职业事实等真实对象进入上下文；深层内容只提供“回到今天”等局部返回动作，不另建全局菜单；
* Agent 只保留一个全局固定入口，放在右下角并避开 toast/主要操作，打开后进入上下文对话抽屉；
* 信息密度以“一个主任务 + 一条旅程 + 一组证据/状态 + 一个下一动作”为上限，避免导航、状态和 AI 入口重复占位。

## Scope Update: Evidence-First Research Completion Layout

用户复核研究页后确认，当前完成态的信息优先级存在反直觉问题：AI 研究任务在完成后仍占据主屏大面积空间，而用户真正需要审阅的证据、冲突与未知项被推到首屏以下。

本轮采用状态感知的信息层级：

1. 研究进行中时，AI 任务轨迹继续占据主要工作区，清楚展示正在读取什么、已产生什么以及还缺什么。
2. 研究完成后，默认主视图切换为建议摘要、证据来源、冲突和未知项；用户应在首屏直接开始审阅依据，而不是先阅读已经完成的过程。
3. 完成后的研究轨迹继续保留，但降为右侧可回看的过程记录，与下一动作和用户决定组成辅助栏；它负责可追溯，不再与证据争夺主位。
4. 桌面端证据列表与当前证据详情保持同屏；辅助栏可以按“下一动作 -> 用户决定 -> 研究过程”排列，优先服务判断和行动。
5. 移动端按“当前建议 -> 证据与未知 -> 下一动作 -> 用户决定 -> 研究过程”重排，不能把已完成过程放在证据之前。
6. 研究尚未完成时不得预先显示演示证据或结论，原有证据生成边界保持不变。
7. 页面顶部的已发生对象轨迹应随对象数量使用可用宽度：对象较少时均分轨道，避免右侧出现大面积空白；对象增加到无法保持最小可读宽度时继续支持横向滚动，不压缩成不可读节点。

新增验收条件：

* [x] 研究完成后的桌面首屏能够看到证据列表和当前证据详情，不需要越过完整 AI 任务轨迹。
* [x] 完成的研究轨迹仍可见且能说明输入、步骤和产出，但视觉权重低于证据与判断。
* [x] 研究进行中仍以任务过程为主，不展示未产生的证据。
* [x] `390x844` 移动端完成态中，证据出现在研究过程之前，页面无横向溢出或不可达操作。
* [x] 两个已发生对象在桌面和移动端均能合理填满轨道；完整对象链仍可横向滚动且节点文字可读。

## Scope Update: Parallel Opportunities, Lifecycle Navigation And Icon System

用户在完整生命周期结果页复核后确认了三个新的产品问题：

1. 当前机会及其研究、决定和后续事件都是单例状态，无法表达真实求职中多个机会并行存在、分别推进和随时切换的情况；页面也缺少清楚的新建机会入口与机会之间的比较视图。
2. 已发生对象链在对象较多时依赖横向滚动，截图中同时出现横向和纵向滚动条。生命周期导航不得要求用户操作嵌套滚动容器，需要改为无滚动、可快速识别当前对象和历史关系的稳定表达。
3. 当前原型实际统一使用 `lucide-react`，不是 Remix Icon。用户希望重新选择一套更精致、风格统一且适合全局替换的图标系统，不能在同一产品中混用不同图标包。

当前已确认目标：

* 支持多个机会并行保存，每个机会拥有独立的研究状态、证据、建议、用户决定、沟通、申请、面试、Offer、结果和策略回写记录。
* 用户始终能发现“新建机会”入口，并能从当前机会回到机会集合、切换其他机会。
* 提供机会比较能力，重点比较会改变投入决定的信息，而不是复制一个通用 CRM 表格。
* 生命周期导航在桌面、平板和移动端均不得产生横向或纵向内部滚动条；历史对象仍可访问，当前阶段和下一动作清楚可见。
* 全局只保留一个图标包，并通过统一尺寸、描边粗细和语义约定使用。

收敛方案：

* 机会状态改为 `opportunities + activeOpportunityId`，每个机会独立保存完整工作区状态；原型预置至少两个不同阶段的虚构机会，并保留继续新建入口。
* 新增安静的机会集合页，不采用看板；支持选择两个或三个机会进入并排比较。
* 比较维度固定为建议、硬约束、匹配、回报与机会成本、关键证据、风险与未知、进展和下一动作；不显示综合分数或自动排名。

* 全局图标包确定为 Phosphor Icons。使用 `@phosphor-icons/react`，默认 `regular` 权重；正文、列表和按钮以 `16px` 为主，重要对象入口使用 `20px`，只有明确的当前/完成状态可以使用 `fill` 或 `bold`，不得与其他图标包混用。

## Engineering Approach

* `prototype/src/app/`：应用入口、路由/视图状态、reducer 和上下文。
* `prototype/src/domain/`：职业事实、机会、证据、研究任务、事件、建议和决定的类型及动作语义。
* `prototype/src/data/`：虚构案例素材、初始空状态、逐步生成的模拟结果和 Agent 回复，不被页面组件直接内联。
* `prototype/src/features/`：首次使用、今天、机会、面试/结果和 Agent 等按业务特性拆分的页面与局部组件。
* `prototype/src/components/`：对象标题、状态标签、证据行、动作按钮、抽屉等可复用视图部件。
* `prototype/src/styles/`：全局 token、布局和特性样式；避免将全部 UI 堆在单个 `App.tsx`。
* 使用单一 reducer 或等价状态边界模拟领域动作，确保“新用户起点 → 示例逐步生成”的顺序可测试；不引入正式路由、状态库或后端选型。

## Scope Update: Product-Grade MVP Interaction Pass

用户确认下一轮目标不是继续增加静态概念页，而是按既定 MVP 功能清单，把核心主链补成一段可完整体验、可反复操作和可回看的产品流程。原型仍使用浏览器内存和虚构数据，但关键动作不得通过点击直接跳过真实输入、处理状态或用户确认。

本轮体验标准：

1. 资料、职位、访谈、面试记录和申请材料等主要输入都必须有真实的录入、选择或上传动作；示例数据只能作为用户明确选择的演示材料，不得覆盖默认输入。
2. 解析、分析和产物生成必须呈现可见的模拟等待、任务步骤、失败/取消或继续路径；完成后保留输入、过程和结果的回看关系。
3. MVP 主链必须补齐职业事实建立、方向与决策标准、职位采集与标准化、研究判断、职位定制材料、沟通草稿、审核清单、用户决定和可读导出。
4. 关键产物必须支持编辑和确认；用户决定需要记录理由，系统建议、证据、风险和未知项不能因生成材料而消失。
5. 同类交互不得存在“表面可编辑但实际忽略输入”的断点；当前重点包括访谈回答、职位正文/来源、面试现场记录、沟通草稿和申请材料。
6. 研究完成后的生命周期扩展继续保留，但必须明确它建立在 MVP 申请决定之后，不把后续能力伪装成已完成的生产功能。
