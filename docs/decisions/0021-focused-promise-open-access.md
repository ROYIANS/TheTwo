# ADR-0021：第一版聚焦产品承诺但不限制使用

## Context

第一版需要聚焦正在主动求职、有数年项目经验的中文软件工程师，才能深入理解其项目经历、技术能力、职位语言和职业路径。但择途同时是面向所有人开放的开源产品，聚焦目标用户并不必然意味着设置使用门槛。

需要区分两类边界：产品对哪些场景承诺经过充分适配，以及哪些用户被允许使用产品。把两者混为一谈，要么会让第一版承担所有职业场景的泛化成本，要么会不必要地拒绝可能从当前能力中受益的用户。

## Decision

1. 第一版只承诺优先服务正在主动求职、有数年真实项目与职业积累的中文软件工程师。
2. 该目标用户定义决定产品研究、领域知识、默认流程和质量验证的优先级。
3. 目标用户定义不是准入限制；应届生、非软件职业人群和暂未求职的用户仍可使用开源产品。
4. 对未充分适配的场景，产品应诚实说明当前能力边界，不暗示已经理解相应行业、招聘规则和职业路径。
5. 长期通过真实用户需求和领域验证逐步扩展受众，不为了名义上的通用性牺牲第一阶段深度。

## Consequences

正面影响：

* 第一版可以围绕真实首位用户和软件工程师求职建立足够深的产品能力；
* 开源产品保持开放，不需要设计职业身份准入机制；
* 非目标用户仍可验证哪些通用能力对其有价值；
* 后续扩展能够基于真实反馈逐个职业领域验证。

代价与风险：

* 非目标用户可能获得质量不稳定或缺乏领域深度的建议；
* 产品需要清楚表达“可以使用”不等于“已经充分适配”；
* 社区贡献可能较早提出跨行业诉求，需要用产品边界控制范围扩张。

## Alternatives Considered

### 只允许目标用户进入主要流程

边界清晰，但需要身份判断和准入机制，也不符合开放项目的使用原则，未采用。

### 第一版承诺服务所有中文求职者

覆盖面更广，但会迫使第一版同时处理校招、跨行业和大量不同招聘规则，削弱软件工程师场景的深度，未采用。

## Supersession

无。
