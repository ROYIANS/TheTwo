# ADR-0011：外部模型与联网服务采用最小必要披露

## Context

择途通过 AI 建立职业画像，并需要使用联网搜索进行公司和职位背调。即使系统由用户自部署并使用 BYOK，发送给模型供应商、搜索服务或其他第三方的数据仍可能离开用户环境。BYOK 只解决模型选择和费用归属，不能自动保证数据最小化或隐私。

系统可以把完整职业画像交给外部模型以获得最充分的上下文，也可以完全禁止画像离开本地，或者根据具体任务只披露必要片段。

## Decision

1. 外部模型、联网搜索和其他第三方服务采用最小必要披露原则。
2. 用户配置 BYOK 不构成系统发送完整职业画像的默认授权。
3. 每项外部能力只发送完成当前任务所需的信息，并让用户能够知道接收方和所含数据类型。
4. 用户可以脱敏或排除敏感字段，也可以在可用时改用本地模型或本地处理。
5. 公司和职位的外部检索默认不携带可识别用户身份。
6. 任务确实需要个人上下文时，只发送用户知情的最小片段。
7. 具体授权交互可以按风险分级，但不能通过模糊的一次性同意隐藏持续的数据外发。

## Consequences

正面影响：

* 自部署与 BYOK 不会被误认为可以忽略第三方数据风险；
* 公司背调等任务可以在不暴露用户身份的情况下完成；
* 用户能够根据敏感程度选择云端或本地能力；
* 外部模型和服务保持可替换，数据边界不依赖单一供应商承诺。

代价与风险：

* 数据裁剪可能降低部分模型任务的上下文完整度；
* 需要定义数据类型、脱敏规则和风险等级；
* 过于频繁的授权提示可能造成确认疲劳；
* 不同模型供应商的数据政策仍需用户理解和选择。

## Alternatives Considered

### 默认发送完整职业画像

模型上下文最完整，实现最直接，但敏感数据暴露范围过大，也会把 BYOK 错当成完整授权，未采用。

### 职业画像永不离开本地

隐私边界最强，但会显著限制用户使用云端模型处理个性化任务，未采用为强制原则。用户仍可选择完全本地的使用方式。

## Supersession

无。
