# ADR-0023：第一版职位内容输入收窄为文本与截图

## Context

ADR-0019 已确认第一版采用用户主动且来源无关的职位输入，并将文本、截图、链接和浏览器当前页面都列为输入方式。继续细化 MVP 后发现，这四种方式的实现和合规成本并不相同。

文本和截图由用户直接提供内容，可以覆盖 BOSS、社区、公众号、公司官网和朋友转述等主要场景。自动读取链接或浏览器当前页面则需要处理网页访问、登录状态、站点变化、浏览器兼容、内容权利和平台限制，不是完成首个“申请就绪”闭环的必要条件。

## Decision

1. 第一版职位正文输入支持用户粘贴文本和上传截图。
2. 用户可以附带职位页面 URL，但 URL 在第一版只作为来源元数据和回访入口保存。
3. 第一版不自动访问、抓取、解析或持续同步用户提供的职位 URL。
4. 浏览器插件和自动读取当前页面属于 MVP 后续能力。
5. 公司与岗位调查仍可以独立检索无需登录即可访问的公开网页；这不等于自动解析用户提交的职位 URL。
6. 公开网页调查优先官方和高可信来源，不访问受限内容、不绕过访问控制，也不进行大规模招聘平台爬取。

## Consequences

正面影响：

* 第一版保留来源无关的职位入口，同时明显缩小浏览器和站点适配范围；
* 截图可以覆盖不便复制或需要登录查看的职位场景；
* 来源记录、职位内容输入和联网调查的边界更加清楚；
* 浏览器插件可以在独立任务中重新核验权限、平台条款和维护成本。

代价与风险：

* 用户需要主动粘贴文本或上传截图，不能仅提交链接完成职位导入；
* 截图提取可能产生识别错误，需要保留原图并允许用户纠正；
* 第一版不会自动同步职位页面的后续变化；
* 产品摘要和后续设计必须避免继续把链接或浏览器当前页描述为首版正文输入方式。

## Alternatives Considered

### 第一版自动解析公开职位链接

操作更方便，但会引入网页访问、内容变化、服务条款和站点适配成本，未采用。

### 第一版同时提供浏览器插件

更贴近用户浏览职位的现场，但会扩大浏览器兼容、权限、发布和平台合规范围，未采用。

### 第一版只支持文本

范围最小，但无法良好覆盖不便复制的招聘平台和图片职位信息，未采用。

## Supersession

本记录部分取代 ADR-0019 中“链接和浏览器当前页面作为第一版职位内容输入方式”的结论；ADR-0019 关于用户主动、来源无关输入和连接器后置的其余决定继续有效。
