# ADR-0005：求职场景覆盖完整决策闭环

## Context

择途的第一个场景是求职。该场景可以只聚焦职位与公司判断，也可以覆盖从认识自己到根据真实求职结果调整策略的完整过程，还可以进一步发展为自动抓取、自动沟通和自动投递的求职机器人。

只做职位判断虽然边界清晰，但无法利用申请和面试结果校正系统对用户与市场的理解，也不能支撑个人职业决策系统所需要的持续反馈。执行自动化则会把产品目标从提高决策质量转向增加投递数量，并削弱用户对关键职业行动的控制。

## Decision

1. 求职场景的长期完整边界是：认识与定位自己、发现并判断机会、准备申请、跟踪沟通与面试、比较 Offer、记录真实结果并调整策略。
2. 求职闭环中的共同核心是支持用户理解信息、权衡选择、准备行动并从结果中学习，而不是单纯生成内容或管理状态。
3. 系统可以协助准备简历、沟通内容和行动计划，也可以在用户授权下导入与整理信息。
4. 系统不自动海投、不冒充用户与招聘方沟通，也不代替用户作出投递、面试、离职或接受 Offer 等关键决定。
5. 完整场景边界不等于 MVP；第一版仍需选择能够独立验证核心价值的最小闭环。

## Consequences

正面影响：

* 真实求职结果能够反馈到职业档案、机会判断和后续策略；
* 各类求职能力可以围绕同一条用户闭环组织，而不是成为孤立工具；
* 用户在关键职业行动中保持主体性；
* 可以明确区分辅助行动与替用户行动。

代价与风险：

* 长期求职场景仍然较大，必须继续收窄 MVP；
* 记录跨阶段结果会增加数据连续性和隐私保护要求；
* 材料生成、状态跟踪和面试准备等能力可能分散注意力，需要始终用决策闭环判断优先级；
* 自动化边界需要在未来连接招聘平台时持续审查。

## Alternatives Considered

### 只做职位与公司判断

无法形成结果反馈，也难以支持持续演化的职业理解，未采用为完整求职场景边界。职位判断仍可能成为 MVP 的核心入口。

### 求职决策与执行全部自动化

自动抓取、沟通、投递和跟进可能提高数量，但会增加平台风控、隐私、真实性和用户失控风险，也与求职者主体性原则冲突，未采用。

## Supersession

无。
