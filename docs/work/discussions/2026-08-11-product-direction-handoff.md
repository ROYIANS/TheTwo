# 择途产品方向讨论交接

本文是项目启动前与其他 AI 讨论结果的结构化交接，不是逐字聊天记录。当前仍有效的内容已提炼到 [`product-brief.md`](../../product/product-brief.md)，本文保留形成过程、能力发散和未决事项。

## 背景

项目发起者是一名普通程序员，面对潜在失业，希望寻找真正适合自己的工作，并建立一个既服务自己、也能帮助其他求职者的开源 AI 平台。

最初设想集中在招聘岗位导入、筛选、简历优化、定制打招呼和面试准备。讨论后，方向从单点“AI 简历工具”扩展为从认识自己到根据真实求职结果调整策略的闭环。

产品只面向中文用户，当前不考虑国际市场。

## 已形成的产品定义

> 一个开源、可信、以求职者为中心的 AI 求职与职业决策平台。它持续理解一个人的真实经历、能力、目标和限制，帮助用户看清机会、准备申请，并根据真实求职结果调整策略。

核心目标是帮助用户作出更好的职业决策并完成下一步行动，而不是生成更多文字。

## 品牌结论

* 中文名：择途
* 英文视觉品牌：THE TWO
* 意向域名：`the-two.life`
* 品牌含义：同一个人的两段人生，带着过去的积累重新主动选择下一程。

当前表达：

> 第一段人生把你带到这里。
>
> 第二段人生，由你选择。

## 已发散的能力地图

### 职业档案与能力证据库

从简历、项目、GitHub 和工作记录中整理经历，区分用户确认事实、AI 推断和证据不足的陈述。AI 只能重组和表达事实，不能虚构经历或业绩数字。

### 职位收件箱与连接器

支持复制职位文本或 URL、浏览器扩展、邮件、文件和正式 API 导入。不同平台的数据需要归一化、去重和风险提示。MVP 不应依赖大规模后台爬取招聘平台。

### 可解释岗位匹配

分析硬性门槛、技能、经验、证据、偏好和机会成本，输出可理解的申请建议、优势、风险与信息缺口，而不是神秘百分数。

### 简历与申请材料

由职业事实库派生岗位定制材料，每一处 AI 修改可接受、拒绝或编辑，并展示事实来源。

### 求职 CRM 与投递看板

记录岗位状态、使用的材料、沟通、时间、面试轮次和结果，逐步形成个人求职漏斗。

### 面试准备与复盘

针对岗位准备项目讲述、预测问题和角色模拟，面试后记录问题与反馈。不做实时隐蔽面试作弊工具。

### 求职漏斗诊断

使用用户自己的真实结果判断问题位于岗位选择、简历表达、沟通、面试还是预期管理。

### 能力差距与作品建设

识别值得补齐的高价值差距，并用短周期、可公开证明的项目或贡献形成真实职业证据。

### Offer 比较

展示薪资、福利、通勤、稳定性、成长和个人目标之间的权衡，不替用户作最终决定。

### 开源与隐私

倾向 local-first、自托管、BYOK、多模型和本地模型。连接器、提示词和评分逻辑应尽量透明可扩展。

## 此前提出的 MVP 草案

曾提出六个主要页面：

1. 我的职业档案；
2. 职位收件箱；
3. 职位分析页；
4. 申请材料页；
5. 投递看板；
6. 面试准备页。

该草案没有被直接接受，需要从目标用户和首要痛点重新验证。

候选最小闭环：

```text
导入真实经历
  -> 导入一个职位
  -> 判断是否值得申请
  -> 生成基于事实的申请材料
  -> 记录结果
  -> 根据结果给出下一步建议
```

## 暂不优先

* 大规模招聘平台后台爬虫；
* 自动海投；
* 企业招聘端和完整社交社区；
* 大量简历模板和自训练大模型；
* 实时面试作弊；
* 无依据匹配分和虚构经历；
* 第一版覆盖所有职业人群。

## 未决事项

1. 第一目标用户是失业或有失业风险的程序员、工作数年但不善表达的程序员，还是转向 AI 应用开发的人；
2. 第一入口是不知道适合什么岗位、不会表达经历、投递无反馈，还是缺少结构化行动计划；
3. MVP 以单个职位申请作战页为中心，还是以职业档案和求职看板为中心；
4. 开源能力、托管服务、模型费用和招聘连接器的长期边界。

## 建议下一步

如果第一版只能帮助一种人解决一个问题，需要先确定：它帮助哪一种处境下的程序员，完成哪一个以前很难完成的结果。
