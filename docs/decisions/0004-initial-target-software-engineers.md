# ADR-0004：第一阶段聚焦有经验的中文软件工程师

## Context

择途首先要服务项目发起者本人即将开始的真实求职。发起者具有 Java、全栈、前端和前端架构经历，需要在质量参差的招聘市场中判断真实且值得投入的机会。

作为开源系统，择途长期希望服务所有中文求职者，并为社区参与和未来商业服务保留空间。但不同行业的能力证据、职位语言、招聘渠道、风险信号和职业路径差异很大。第一版如果同时覆盖所有职业，很可能只能提供浅层通用建议。

## Decision

1. 项目发起者本人是择途的首位参考用户，第一版以其真实求职结果检验产品价值。
2. 第一阶段主要服务正在主动求职、有数年真实项目与职业积累的中文软件工程师，包括前端、后端和全栈等开发方向。
3. 长期目标受众是所有中文求职者，但职业范围必须根据真实需求、领域知识和已验证产品能力逐步扩展。
4. 产品概念应避免无必要地绑定单一编程语言或前端岗位，但第一阶段不为尚未服务的职业牺牲判断深度。
5. 更广受众带来的商业可能性是未来探索方向，不作为第一版扩大范围的理由。

## Consequences

正面影响：

* 能够立即服务项目发起者的真实求职，并快速获得反馈；
* 职业档案、职位判断和公司背调可以针对软件行业形成足够深度；
* 初期需求和验证对象更清晰；
* 长期仍保留向其他中文职业人群扩展的空间。

代价与风险：

* 初期用户规模和可覆盖岗位范围较窄；
* 软件行业形成的概念不能被误认为适用于所有职业；
* 未来扩展到其他职业时，需要补充领域知识并重新验证能力模型；
* 项目发起者的个人需求可能被过度代表，需要用其他目标用户反馈校正。

## Alternatives Considered

### 第一阶段覆盖所有中文互联网从业者

产品、设计、测试、运营和开发的能力证据与招聘逻辑差异较大，第一版难以同时做到深入，未采用。

### 第一阶段覆盖所有中文求职者

受众规模更大，也可能更早探索商业化，但会迫使第一版使用泛化程度过高的建议和数据结构，未采用。

### 只为项目发起者个人开发

能最快满足当前需求，但容易固化为一次性个人脚本，无法形成可复用的开源产品，未采用。

## Supersession

无。
