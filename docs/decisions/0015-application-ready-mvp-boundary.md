# ADR-0015：第一版以申请就绪为终点并保留用户对外行动权

## Context

第一版可以在系统判断一个机会是否值得申请后结束，也可以继续准备岗位定制材料，或者进一步记录申请结果形成反馈闭环。产品还需要明确自动化是否可以延伸到在招聘平台代表用户沟通和投递。

只完成机会判断会让用户仍需手工把判断转换成申请材料；完整结果反馈能够支持策略校正，但会扩大第一版范围。自动沟通和海投可能增加投递数量，却与用户主体性、平台规则和真实表达原则冲突。

## Decision

1. 第一版 MVP 的终点是“申请就绪”。
2. 系统对值得申请的岗位生成基于已确认职业事实的定制申请材料和沟通草稿，交由用户审核、修改和使用。
3. 用户亲自在 Boss 等招聘平台沟通和投递；系统不冒充用户发送消息、不自动提交申请，也不进行自动海投。
4. 自动化可以用于信息提取、联网调查、职业画像维护、机会比较、材料草拟和流程提醒，只要不越过用户对外沟通与关键职业行动的控制权。
5. 申请结果记录与策略反馈属于完整求职场景，但不是第一版达到“申请就绪”的必要终点。

## Consequences

正面影响：

* 用户从机会判断可以直接进入可执行状态；
* 申请材料共享同一份已确认职业事实，减少虚构和表达漂移；
* 用户保留对外表达、沟通和投递的控制；
* 第一版不必同时实现完整求职 CRM 和结果诊断。

代价与风险：

* 第一版无法在产品内部自动形成完整的结果反馈数据；
* 用户仍需手动在招聘平台完成沟通和投递；
* “申请就绪”包含哪些材料仍需继续收窄；
* 浏览器扩展等能力需要严格区分读取当前页面与代替用户操作页面。

## Alternatives Considered

### 在机会判断后结束

范围最小，但没有帮助用户把判断转化为下一步申请行动，未采用。

### 第一版包含结果反馈闭环

更符合长期求职闭环，但会把状态跟踪、结果记录和策略校正同时带入首版，暂不采用为必要终点。

### 自动沟通和自动投递

可能提升操作效率，但会削弱用户主体性，并增加平台合规、账号风控和真实性风险，未采用。

## Supersession

无。
